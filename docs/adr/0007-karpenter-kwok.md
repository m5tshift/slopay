# 0007. Автомасштабирование узлов: Karpenter с провайдером KWOK

## Контекст

Требуется автомасштабирование узлов кластера (SRS INF-1.2, приоритет Should). Кластер работает в VM
Hyper-V на одном ПК: 1 control plane и 3 рабочих узла. Под VM выделено 26,5 из 32 ГБ, Windows остаётся
около 5,5 ГБ (SRS 6.1). Постоянная нагрузка занимает рабочие узлы целиком (SRS 6.2).

## Решение

Karpenter с провайдером KWOK (SRS INF-1.2):

- решения о добавлении и удалении узлов настоящие, сами узлы имитируются;
- Karpenter с kwok-провайдером собирается из исходников и публикуется в Zot;
- имитируемые узлы несут taint, toleration к нему есть только у демонстрационной нагрузки: поды Системы
  на них не размещаются.

## Рассмотренные варианты

- **Настоящие узлы в новых VM Hyper-V.** Свободной памяти на ПК под новые VM нет (SRS 6.1).
- **Без автомасштабирования узлов.** Требование INF-1.2 не выполняется.
- **Karpenter с провайдером KWOK** (выбран).

## Последствия

- Автомасштабирование демонстрирует решения планировщика, а не рост мощности: нагрузка Системы новых
  ресурсов не получает.
- Демонстрационная нагрузка отделена от Системы taint'ом: поды Системы остаются на трёх рабочих узлах.
- Нужна своя сборка Karpenter (`infra/karpenter-kwok/`) и публикация образа в Zot.
- Karpenter работает в неймспейсе `karpenter` и входит в бюджет операторов (SRS 4.4, 6.2).
