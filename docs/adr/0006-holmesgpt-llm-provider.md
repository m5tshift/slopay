# 0006. LLM-провайдер для HolmesGPT

## Контекст

HolmesGPT разбирает вероятную причину алерта и для этого обращается к LLM (SRS 4.5.5). Разбор приходит
в Telegram не позже 2 мин после алерта (SRS 8.9). Постоянная нагрузка занимает рабочие узлы целиком,
свободной памяти под локальную модель в бюджете стенда нет (SRS 6.2). Внешний LLM-API может быть недоступен
или исчерпать лимит (SRS раздел 10). Разбор носит рекомендательный характер: действия выполняются по runbook
(SRS 4.5.5).

## Решение

- Основной провайдер — DeepSeek API через LiteLLM, модель `deepseek/deepseek-chat` (SRS 4.5.5).
- Резервный — локальная модель Qwen 3.5 9B через Ollama, вне бюджета стенда. Она запускается только при
  временно остановленной части стенда (SRS 6.2).
- Ключ LLM-провайдера хранится в OpenBao.

## Рассмотренные варианты

- **Только локальная модель.** Для неё нет памяти в бюджете стенда (SRS 6.2).
- **Только внешний API.** При его недоступности AI-разбора нет, остаётся только ручная работа по runbook
  (SRS раздел 10).
- **Внешний API и локальный резерв** (выбран).

Выбор DeepSeek среди внешних провайдеров SRS не обосновывает.

## Последствия

- Текст и метки алертов, а также собранные HolmesGPT метрики, логи и трейсы уходят во внешний API.
  Доступ HolmesGPT к кластеру — ClusterRole только `get/list/watch` без доступа к `Secret`, toolset
  Kubernetes Remediation отключён; секреты в логи сервисов не попадают (SRS 4.5.5).
- При недоступности внешнего API алерты и runbook работают без разбора; остаётся ручной режим через CLI
  HolmesGPT (SRS раздел 10).
- Резервная модель работает только вне испытаний и при частично остановленном стенде.
