# 0005. Хранение только xpub

## Контекст

На каждый счёт Система выдаёт уникальный адрес (SRS FR-02). Мерчант хочет принимать платежи, не передавая
приватные ключи (SRS US-10). Платформа средства не хранит, комиссия выставляется мерчанту отдельно
(SRS FR-12). xpub — расширенный публичный ключ: он позволяет выводить адреса без приватного ключа
(SRS раздел 11).

## Решение

Система хранит только xpub мерчанта, приватных ключей нет (SRS 4.1.10):

- Мерчант загружает xpub при регистрации. Система проверяет формат и выводит первый адрес для сверки
  с кошельком мерчанта (SRS UC-06).
- Адрес счёта выводится из xpub. Индекс деривации — атомарный счётчик на мерчанта в PostgreSQL; уникальный
  индекс `(merchant_id, derivation_index)` исключает выдачу одного адреса двум счетам (SRS 4.1.3).
- Приватных ключей и мнемоник мерчантов нет в коде, тестах и логах. Тестовая мнемоника Anvil хранится только
  в секрете стенда (SRS раздел 5).

## Рассмотренные варианты

- **Платформа хранит ключи адресов и принимает средства на себя.** Противоречит SRS US-10 (мерчант
  не передаёт приватные ключи) и FR-12 (платформа средства не хранит).
- **Только xpub** (выбран).

## Последствия

- Средства сразу поступают на адреса мерчанта. Платформа не может их перевести: комиссия 0,5 % учитывается
  в `ledger-service` как долг мерчанта платформе и выставляется отдельно (SRS 4.1.3, FR-12).
- Переводы после окна отслеживания Система не обрабатывает, средства остаются на адресе из xpub мерчанта
  (SRS 4.1.4).
- Утечка данных Системы не даёт доступа к средствам мерчантов: приватных ключей в ней нет.
- Вывод адресов из xpub входит в список обязательного ручного ревью (SRS раздел 7, п. 5).
