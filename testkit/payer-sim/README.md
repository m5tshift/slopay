# payer-sim

Покупатель-имитатор (SRS 4.1.3, 8.1, 8.5): оплачивает счета ETH в Anvil с заранее пополненных счетов и по команде
повторно отправляет сохранённые подписанные транзакции. Контракт API:
[`contracts/openapi/payer-sim.yaml`](../../contracts/openapi/payer-sim.yaml).

## Как работает

1. Клиент (Locust, скрипт стенда) после создания счёта вызывает `POST /payments {"invoiceId": "..."}`.
2. payer-sim читает адрес и сумму из `GET /pay/{id}` у `invoice-service` (`PaymentPage`). Счета не в ETH не оплачиваются.
3. По долям из конфигурации решает: оплатить полностью, недоплатить (`UNDERPAY_BPS` от суммы, вниз, не меньше 1 wei) или не платить.
   Решение принимается один раз на счёт: повторный вызов возвращает то же решение и ничего не отправляет.
4. Подписывает перевод (legacy-транзакция, 21000 газа, цена газа вдвое выше предложенной нодой) с очередного счёта
   по кругу, nonce ведёт локально и сверяет с нодой после ошибки отправки.
5. Подписанные транзакции хранятся в памяти. `POST /control/replay` (все или `{"invoiceId": "..."}`) отправляет их
   заново в порядке подписания: после `anvil_reorg` или `evm_revert` тот же `txHash` снова попадает в цепочку (SRS 8.5).
   Транзакция, которую нода уже знает, ошибкой не считается.

| Запрос | Действие |
|---|---|
| `POST /payments` | оплатить счёт по долям |
| `GET /payments` | все платежи по порядку |
| `POST /control/replay` | повторно отправить сохранённые транзакции |

Состояние в памяти, одна реплика: рестарт забывает транзакции. Аутентификации нет, компонент доступен только внутри mesh.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `HTTP_ADDR` | адрес HTTP | `:8080` |
| `LOG_LEVEL` | уровень логов | `info` |
| `INVOICE_SERVICE_URL` | адрес `invoice-service` | обязательна |
| `ANVIL_RPC_URL` | JSON-RPC Anvil | обязательна |
| `PAYER_KEYS_FILE` | файл секрета: по одному hex-ключу пополненного счёта в строке (`0x` необязателен, `#` — комментарий) | обязательна |
| `PAY_PERCENT`, `UNDERPAY_PERCENT`, `SKIP_PERCENT` | доли «оплатить / недоплатить / не платить», сумма 100 | `80`, `10`, `10` |
| `UNDERPAY_BPS` | какую часть суммы отправляет недоплачивающий, б. п. (1–9000) | `5000` |

Ключи берутся только из смонтированного секрета стенда и в логи не попадают. В репозитории их нет.
